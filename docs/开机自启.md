# 开机自启与已有部署升级

2026-11-03 更新：PMHQ 与 LLBot 的 Compose 默认重启策略均为 `unless-stopped`。本项只改变容器启动策略，不改变认证、端口、QQ资料、消息处理或资源上限。

## 首次部署

按 README 初始化并构建后运行：

```sh
docker compose config --quiet
docker compose up -d
```

Linux/systemd 主机检查 Docker 服务是否随系统启动：

```sh
systemctl is-enabled docker
# 未启用时，由有权限的管理员运行：
sudo systemctl enable --now docker
```

Docker Desktop 或其他初始化系统应使用对应的 Docker 启动设置，不要直接套用 systemctl。

## 升级已创建的容器

先备份当前 compose.yaml，并按原有方法备份 state。更新本项目的 compose.yaml 后，在原项目目录执行：

```sh
docker compose config --quiet
# -a 包括已停止的容器；每个服务必须恰好存在一个容器。
for service in pmhq llbot; do
  ids=$(docker compose ps -a -q "$service") || exit 1
  set -- $ids
  if [ "$#" -ne 1 ]; then
    echo "Expected exactly one existing container for $service" >&2
    exit 1
  fi
  docker update --restart unless-stopped "$1" || exit 1
done
docker compose start pmhq llbot
```

这组命令更新已有容器的策略并启动已停止的服务，不重建容器。服务名 pmhq/llbot 对应本仓库配方；自行部署的实例须核对实际项目和服务名，不能按名称匹配启动旧备份容器。没有创建容器时使用首次部署步骤。

验证实际策略和运行状态：

```sh
for service in pmhq llbot; do
  ids=$(docker compose ps -a -q "$service") || exit 1
  set -- $ids
  [ "$#" -eq 1 ] || exit 1
  docker inspect --format '{{.Name}} restart={{.HostConfig.RestartPolicy.Name}} status={{.State.Status}}' "$1"
done
docker compose ps
```

容器运行不代表 QQ 已登录。打开 WebUI，确认 PMHQ 已连接及 QQ 在线；保存会话未恢复时需要重新扫码。不要为检查自启而在业务期间直接重启整机或 Docker。

## 停止、恢复和回滚

- `docker compose stop`：主动停止；unless-stopped 会保留这一停止状态，后续重启 Docker/整机也不会主动恢复。
- `docker compose start`：恢复已创建的服务，并重新启用其自动恢复行为。
- `docker compose down`：删除容器；必须再用 up -d 创建，重启策略不会创建不存在的容器。
- 取消自动恢复：把两个服务的 restart 改回 `"no"`，并对核实过的容器执行 `docker update --restart=no CONTAINER_ID`。仅改 YAML 不影响现有容器。
- PMHQ 启动器只在自己的容器命名空间内清理遗留 X99 锁并监督 QQ 主进程。无需额外添加 cron 或重复的守护任务。
